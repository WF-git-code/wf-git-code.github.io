1. 设计模式基础概念

1.1 定义

设计模式是软件设计中反复出现问题的标准化解决方案，基于面向对象思想，封装变化、解耦代码、提升复用与可维护性。

1.2 三大分类

  1. 创建型：管控对象创建逻辑，隔离实例化细节
  2. 结构型：组合多个类 / 对象形成复杂结构
  3. 行为型：划分对象职责、规范对象间交互通信

1.3 C++ 核心面向对象支撑

  • 封装：访问控制 public/private/protected
  • 继承：公有 / 保护 / 私有继承，虚继承解决菱形继承
  • 多态：虚函数 virtual、纯虚函数（抽象类）
  • 动态内存：new/delete、智能指针 shared_ptr/unique_ptr
  • 模板：泛型，辅助工厂、迭代器等模式实现

2. 创建型模式（5 种）

2.1 单例模式 Singleton

适用场景

全局唯一资源：日志管理器、数据库连接池、配置管理器

核心要点

  1. 私有化构造函数，禁止外部实例化
  2. 提供静态方法获取唯一实例
  3. C++ 两种实现：懒汉、饿汉、线程安全版

饿汉式（程序启动即创建，天然线程安全）

线程安全懒汉（C++11 magic stati

优缺点

  • 优点：全局唯一、减少内存开销
  • 缺点：违背单一职责、难以单元测试、销毁顺序不可控

2.2 工厂方法 Factory Method

适用场景

产品类型会扩展，将对象创建延迟到子类

结构

  1. 抽象产品：基类
  2. 具体产品：产品实现类
  3. 抽象工厂：工厂基类，声明纯虚创建方法
  4. 具体工厂：对应产品的工厂，实现创建逻辑

优缺点

  • 优点：新增产品只加产品类 + 工厂类，符合开闭原则
  • 缺点：类数量爆炸，层级复杂

2.3 抽象工厂 Abstract Factory

适用场景

存在多产品族，一组相关产品统一创建（如 UI 套件：按钮 + 文本框）

结构

  • 多个抽象产品、多组具体产品
  • 抽象工厂定义一组创建接口
  • 具体工厂实现整套产品族创建

优缺点

  • 优点：保证同一产品族产品配套使用
  • 缺点：新增产品等级需修改所有工厂，违反开闭

2.4 建造者 Builder

适用场景

对象构造步骤复杂、构造流程固定，但部件组合不同（电脑组装、套餐）

角色

  1. Product：复杂产品
  2. Builder：抽象建造者，定义组装步骤
  3. ConcreteBuilder：具体建造，实现部件构造
  4. Director：指挥者，统一组装流程

优缺点

  • 优点：构造与表示分离、分步构建、精细控制构造过程
  • 缺点：产品结构差异大则不适用

2.5 原型 Prototype

适用场景

创建对象成本高，通过克隆复制已有实例（文档模板、游戏角色）

核心：克隆 clone() 虚接口

优缺点

  • 优点：跳过复杂构造、动态创建对象
  • 缺点：深拷贝 / 浅拷贝容易出错，循环引用难处理

3. 结构型模式（7 种）

3.1 适配器 Adapter

场景

兼容不兼容接口：旧代码复用、第三方库适配

  1. 类适配器（多继承，C++ 慎用）
  2. 对象适配器（组合优先，推荐）

对象适配器示例

3.2 桥接 Bridge

核心：多维度拆分，组合代替继承

场景：图形 + 颜色、设备 + 操作系统

  • 抽象层持有实现层指针，两个维度独立扩展

优点

避免多层继承爆炸，两个变化维度完全解耦

3.3 组合 Composite

场景：树形结构统一处理（文件目录、菜单、组织树）

  • 叶子节点：无子节点

  • 容器节点：可添加 / 删除子节点

    统一提供

    接口，客户端无需区分叶子 / 容器

3.4 装饰 Decorator

场景：动态给对象新增功能，替代继承扩展

核心：装饰器继承基类，内部持有基类对象，层层包装

例：IO 流、咖啡加配料、消息加密

和适配器区别

  • 装饰：增强原有功能，接口不变
  • 适配器：转换接口，适配不同规范

3.5 外观 Facade 门面

场景：复杂子系统封装统一入口

提供高层接口，隐藏内部多类复杂调用（电脑开机、多媒体播放器）

优点

简化调用、解耦客户端与子系统

3.6 享元 Flyweight

场景：大量重复细粒度对象，节约内存（文字字符、游戏粒子）

  • 内部状态：不变，共享
  • 外部状态：变化，外部传入
  • 享元工厂统一缓存复用对象

3.7 代理 Proxy

分类

  1. 远程代理：访问网络对象
  2. 虚拟代理：延迟加载大资源（图片）
  3. 保护代理：权限校验
  4. 智能指针代理：shared_ptr 底层思想

核心

代理与真实主题实现同一抽象接口，代理预处理 / 后置处理再调用真实对象

4. 行为型模式（11 种）

4.1 责任链 Chain of Responsibility

场景：请求分层处理，每个节点可处理 / 转发（日志分级、审批流）

  • 处理器持有下一级处理器指针
  • 请求沿链条传递，直到被处理或链条结束

优点

请求发送者与接收者解耦，动态调整处理链路

4.2 命令 Command

场景：封装操作为对象，支持撤销、队列、日志、回放

角色：

  • Command：抽象命令 execute() / undo()
  • ConcreteCommand：绑定接收者，执行具体操作
  • Invoker：调用者，持有命令对象
  • Receiver：真正执行业务的类

典型应用：编辑器撤销、GUI 按钮指令

4.3 迭代器 Iterator

场景：统一遍历不同容器，隐藏存储结构

C++ STL 容器全部内置迭代器，完全遵循该模式

  • 抽象迭代器：next()/hasNext()
  • 容器提供创建迭代器接口

4.4 中介 Mediator

场景：多对象复杂交互，用中介统一中转（聊天室、窗口组件）

消除多对多依赖，转为对象与中介一对多

4.5 备忘录 Memento

场景：保存对象快照，支持回滚（文本撤销、游戏存档）

三角色：原发器、备忘录、负责人

负责人只存储快照，不能访问快照内部数据，封装完好

4.6 观察者 Observer（发布订阅）

场景：一对多通知，状态变更自动推送（事件总线、GUI 监听）

  • 主题 Subject：维护观察者列表，通知广播
  • 观察者 Observer：接收更新 update()

4.7 状态 State

场景：对象行为依赖自身状态，状态切换分流逻辑（订单、游戏角色）

每个状态独立成类，消除大量 if-else/switch，状态间自由切换

4.8 策略 Strategy

场景：算法动态替换，同一行为多种实现（排序算法、支付方式）

  • 策略基类封装算法接口
  • 上下文持有策略对象，运行时替换

和模板方法区别

策略：算法整体互换；模板：固定流程，局部步骤扩展

4.9 模板方法 Template Method

场景：固定算法骨架，延迟部分步骤到子类（框架流程）

基类定义主流程虚函数，子类重写钩子 / 步骤，流程不可修改

4.10 访问者 Visitor

场景：稳定数据结构，频繁新增操作（编译器语法树解析）

双分派：元素接收访问者，访问者重载处理不同元素；新增操作不用修改元素类

缺点：结构修改时改动巨大

4.11 解释器 Interpreter

场景：自定义语法解析（正则、脚本表达式、计算器）

构建语法树，递归解释执行；日常开发极少使用

5. 六大设计原则（设计模式底层准则）

5.1 单一职责 SRP

一个类只负责一件事，降低修改影响范围

5.2 开闭原则 OCP

对扩展开放，对修改关闭；新增功能不改动原有代码（工厂、策略、模板）

5.3 里氏替换 LSP

子类完全替代父类，重写不破坏父类行为

5.4 依赖倒置 DIP

高层模块不依赖低层，二者依赖抽象；面向接口编程而非具体类

5.5 接口隔离 ISP

客户端不依赖不需要的接口，拆分粗接口为细粒度专用接口

5.6 最少知道（迪米特）LOD

类只和直接朋友通信，减少类间耦合

6. 模式选型速查表

创建型选型

  • 全局唯一对象 → 单例
  • 单一产品扩展 → 工厂方法
  • 多组配套产品 → 抽象工厂
  • 复杂多步骤构造 → 建造者
  • 复制创建代价高 → 原型

结构型选型

  • 兼容旧接口 → 适配器
  • 两个维度独立扩展 → 桥接
  • 树形层级结构 → 组合
  • 动态叠加功能 → 装饰
  • 简化复杂系统调用 → 外观
  • 大量重复对象省内存 → 享元
  • 控制对象访问 / 延迟加载 → 代理

行为型选型

  • 请求逐级处理 → 责任链
  • 操作可撤销 / 排队 → 命令
  • 统一遍历容器 → 迭代器
  • 多对象解耦通信 → 中介
  • 对象状态回滚存档 → 备忘录
  • 状态变更广播通知 → 观察者
  • 行为随状态变化 → 状态
  • 动态切换算法 → 策略
  • 固定流程局部扩展 → 模板方法
  • 稳定结构频繁加操作 → 访问者
  • 自定义语法解析 → 解释器
